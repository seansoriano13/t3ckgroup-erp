Purchasing Demo Run Sheet

One real government deal, from Lead to a filed IPAS, demonstrating the Purchasing subsystem. Deal is Odoo sale order S03204: Marikina City Government, fire-fighting equipment, 12 product lines, ₱1,370,535.74, procured across four real P0s. Part 0 is setup. Parts 1 to 9 are the live run. Parts A to F are targeted side scenarios. Tick each step as completed.

Branch state: Updated for v1.9.86 (#877: a Technical page for the RRD and IOE teams; #875: Fetch from Odoo is back on the registration form; #876: compact SOR header). Earlier, PR #867 / v1.9.85 (bulk line status triage with unified Undo, search highlighting across Purchasing lists, recent activity sort on Dashboard, tinted top line for Attach P0, clickable IPAS links in attach notifications, and S0 card in Details edit form). Action-only: Who, Where, Do, See.

Run Sheet Structure

Four rows per step

Who: Login account and role. Where: Navigation path and component. Do: Exact click or input action. See: Verified system response and screen output.

Stage departure gates

A gate on a stage stops the deal from leaving that stage. It does not stop arrival. Example: "Costing priced" on PMS Sourcing GS evaluates when Sales advances from PMS Sourcing GS to Proposal Submitted.

Four isolated browser sessions

Sales: Chrome (dani@demo). Purchasing: Chrome Incognito (cjay@demo). Signers: Edge (switch between grace, jelai, 101, 201, jen). Warehouse: Edge InPrivate (aldrin, sherwin).
