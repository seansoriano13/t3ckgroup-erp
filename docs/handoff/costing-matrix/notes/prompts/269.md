Same rounding as costingMath.markupPrice; add a test that they agree.
- costingMath: markupPrice (null on blank Acquire); each line's Markup Price sum; achieved markup per line (Final Offer total ÷ its Components' Acquire total) and overall (counting cost-only rows), computed only when inputs are present (only closed_book has them). Nothing ever fills Final Offer.
- Grid: factor shown as ×1.35 and +35% (closed book only); Markup Price per row and each line's sum beside Final Offer (price + closed book); achieved-vs-target per line and overall in the header (closed book only).
- Settings: create a "Costing Matrix" tab in the Purchasing Module settings (PurchasingSettings), built from standalone sections in `src/components/costing/settings/`: `CostingMatrixSettings.jsx` (a trivial list of sections) and `MarkupPresetsSection.jsx`. #270 and #271 add their own sections in parallel; keep the list trivial to merge. Tab visible to Super Admin, Purchasing access and Final Acquire list members.

- Acceptance tests from the ticket (unit: ×1.47 vehicle, ×1.00 ₱100,000 delivery; blank Acquire → null; cost-only rows change overall not line; factor change leaves Final Offer; policy: Sales refused default factor and overrides, plain employee refused presets; service: preset sets default factor, row override survives a default change).
