## Failures

### F1 · Final Acquire list cannot open the SOR from the Bid Decisions queue (CM-15)
- Expected: the approver opens the matrix from `/approvals/bid-decisions` and decides.
- Saw: the row is listed with totals, but opening it says "You don't have access — You're not on this SOR." It only worked after the Deal Owner mentioned the approver in the SOR notes, and that access ends when the stage moves.

### F2 · Evaluation list members can never see the matrix (CM-09, CM-10, CM-11)
- Expected: someone on the Evaluation list approves the Evaluation.
- Saw: ops-head (Evaluation list only) cannot open the SOR. After a mention the SOR opens, but the PMS tab is blank. In the database, `costing_tier()` gives no tier to the Evaluation list, and a mention is not a tier. So an Evaluation-list member who is not also Purchasing or Deal Team can never approve. The run continued by adding purchaser-2 to the list.

### F3 · Costing Matrix number boxes are too narrow to read (CM-02, minor)
- Saw: Tender Line quantity 4 shows as an empty box, and ABC 9000 shows as "90".

### F4 · A made-up PO number is stored as "verified" (PR, item set to Ordered)
- Expected: the app checks the PO number against Odoo itself.
- Saw: the browser sends its own "verified" mark and the database trusts it. A fake PO, P1234567, was saved as VERIFIED.

### F5 · A purchaser can give "Checked by" on the Computation status (IPAS-21)
- Expected: guide §9 says only Finance, or a Super Admin who is not in Purchasing, gives Checked by.
- Saw: as the purchaser, after LC Odoo Done, the "Checked by" button was clickable and it saved. The history reads "Computation status: Checked by · Mock Purchaser".
- Cause: `ipas_set_header` only limits people outside Purchasing. Purchasing may set any status (migration `20261014120000`, near line 340).

## Things to check (not counted as failures yet)

- **Current Computation status looks unselected:** the active step is drawn plain, so "Checked by" looked not given when it was.
- **Section numbers disagree inside the app:** the IPAS screen says 1 Purchasing, 2 Purchasing & Finance, 4 Filing; Settings and notifications say sections 1, 3 and 7.
- **"Your move" names the slip's next step, not yours:** the technical user is told "Waiting for you: Received in Odoo", which they cannot do.
- **Transmittal prepared time shows 08:00 AM** for a slip made near 5 PM.
- **Wrong name on the Filing step:** it says "Waiting for Finance to receive it", but the receiver is the operations head (the Received list).
- **Odoo refresh on open:** the "fetched" time did not change when the IPAS was reopened. The refresh may be throttled, or may not have run.
- **No edit control for Remarks or the SOR list** on the IPAS screen, so IPAS-22's "change remarks / change the SORs" has nothing to try.

- **Possible money leak:** the price tier (sales-exec) sees "Landed Cost / unit" and "Landed Cost total" columns. They were empty during the run. Check once an IPAS feeds Landed Cost.
- **Layout:** the SOR window slides sideways and leaves a blank strip when the Component grid is in focus (seen 3 times).
- **Layout:** the SOR window jumped from PMS back to Summary once while editing.
- **Every purchaser joins Project requests:** purchaser-2 became a member of the Project request, so guide §6 ("a non-member purchaser stops seeing it") cannot happen. Guide or behaviour is out of date.
- **AUD reference rate:** a Super Admin can override any currency (AUD worked). The code does this on purpose. Guide §8/§14 says only USD/EUR.
- **Refusals as server errors:** several IPAS refusals (sign order, send back, remove document) return error 500 instead of a normal refusal.
- **Condition preview** shows the raw name "purchasing_settled".
- **Purchaser's and finance's menus** show a Flow Canvas link (likely read-only for all).

## Setup problems found (fixed locally, not app bugs)

- The local database had **no published Sales Flow**. FLOW-00 was built by hand (Lead → Costing → Bid → Award → Done).
- The seed SORs are owned by the Super Admin, not sales-exec, and have no matrix. The run used a fresh SOR: "Mock Client Story FLOW - rescue gear" (SOR-352, S07270 from Odoo).
- **Local DB drift:** the stage-condition rule was missing two kinds although the ledger said the migrations ran. Re-ran `20261018180000`, `20261018190000`, then `20261018220000` locally to restore the latest functions.
- Reference rates were empty locally until `currency-rates-fetch` was run by hand.
